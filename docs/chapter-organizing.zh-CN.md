# 按章整理输出视频

缓存元数据里通常没有章节名。这份说明给出一个可重复的做法，把已经转换好的 MP4 按教材章节分组，不改解密流程。

## 缓存里有什么

`_log` 一般包含 `course_id`、`course_section_id`、`group_name`、`video_id`、`video_name`、`duration`、`url`。目前见到的缓存里 `course_section_id` 是每个视频一个独立值，`group_name` 多为空。缓存只能提供视频级元数据，不能直接当章节索引。

## 用教材目录定章

1. 从官方教材 PDF 的书签读取章名和章序，书签标题通常是权威的章节名。
2. 和视频顺序对照。多数课程按教材章序录制。
3. 用“本章总结”找章界。名字类似“本章总结”的视频通常是一章的最后一条。
4. 校验每个视频只归入一章，并核对每章数量是否合理。

## 建议结构

```text
<输出目录>/<课程名>/
  00_导学与教材变化/
    01_<video_id>_<标题>.mp4
  第01章_<章名>/
    01_<video_id>_<标题>.mp4
    ...
    08_<video_id>_本章总结.mp4
  第02章_<章名>/
    ...
```

- 章号和章内序号都用两位数，文件管理器排序才正确。
- 文件名保留 `video_id`，它是去重和追溯的稳定主键。
- “本章总结”放在所属章最后。单独建“总结”目录会让复习多跳一次。
- 导学、教材变化等不属于正文的视频放 `00_导学与教材变化`。文件名没有章归属时不要猜。

## 映射留在本地

本地维护一份 JSON，字段包括 `chapter`、`order`、`video_id`、`name`、`file`，再生成一份给人看的 CSV 索引。两者都含真实课程和视频 ID，只留在本地工作区，不提交到仓库。`.gitignore` 已覆盖常见文件名。

## 校验

- 每个视频只分配一次；章数量与教材和课程总数对得上。
- 用处理时相同的 `OUT` 和 `TARGET_COURSES` 运行 `verify_output.js`。
- 再运行一次 `batch_process.js`。它会按 `video_id` 递归查找子目录，已整理的文件会被跳过，不会重转。
- 抽 1–2 个输出用 ffmpeg 解码 60 秒，确认容器和流正常。

## 容易踩的点

- 后补视频的 ID 可能大于“本章总结”，按内容插到总结前。
- 有的章没有“本章总结”视频，不要补占位。
- 不要改文件名清洗规则。已有输出判断和重跑都依赖稳定的文件名。
- 教材变化类视频单独核对，名字常常很泛，必要时手动归位。
